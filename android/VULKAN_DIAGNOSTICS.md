# Диагностика Vulkan на Android

APK для диагностики сохраняет журнал лаунчера и нативный журнал движка за каждый запуск. Лаунчер записывает выбранный рендерер, профиль качества, разрешение, Android SDK, модель устройства и ABI. Движок помечает стадии `probe`, `requirements`, `module.selected`, `device.create`, `gpu.ready`, `swapchain`, `materials.ready`, `level.load`, `frame.progress`, `android.lifecycle`, `level.unload`, `device.destroy`. Ошибки материалов включают имя shader и ID; ошибки Vulkan validation попадают в нативный журнал с VUID.

Для проверки выберите в лаунчере **Vulkan** (явно), запустите игру, затем откройте экран журналов лаунчера и экспортируйте журналы этого запуска. При сбое до появления главного меню приложите и журнал лаунчера, и нативный журнал целиком. При проблеме в уровне укажите игру, уровень, действия перед ошибкой и время возникновения. В диагностическом APK validation layer включается автоматически для проверки треугольника; для игры его можно включить дополнительным аргументом `-vk_validation`. Проверка треугольника завершает работу через 3,5 секунды после результата, поэтому возврат в лаунчер сам по себе не означает сбой. Архивы игровых данных остаются на устройстве и не требуются для передачи журналов.

Сборка и host-тесты проверяют код и упаковку без устройства. Это не подтверждает работоспособность игровых shader families: незнакомые материалы должны явно остановить загрузку и оставить диагностическое имя в журнале.
