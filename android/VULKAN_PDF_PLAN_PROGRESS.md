# Статус 33 задач из PDF «OpenXRay Vulkan: план завершения 102–103»

Источник: присланный пользователем `openxray-vulkan-plan-102-103.pdf`, 12.10.2026. Нумерация ниже относится к **этому PDF**, а не к пунктам 1–103 старого `VULKAN_RENDERER_PLAN.md`. [Конечная цель и правило неизменяемого объёма](VULKAN_FINISH_LINE.md) отделяют исходные подпункты от новых самостоятельных задач. Состояние отражает текущее дерево ветки PR. «Частично» означает, что критерий «Готово, когда» в PDF ещё не доказан. Изображение и frame-time на устройстве не проверены.

Предыдущий срез 14.10.2026: `BmmD` v3 сохраняет четыре `R2-*` слота, четыре `$null` допускают одноканальный detail, неполный набор получает точный отказ. Тогда opaque `MODELEbB` отклонялся при разрешении материала; этот отказ исправлен после сверки с исходным `uber_deffer("model", "base")`. Семь профильных host-тестов прошли. ARM64-only APK 0.9.133 этого предыдущего среза имел SHA-256 `34619979eacae421c3d8124c7f7fbb80c3b557161f1c8307fed40d8b136efdcb`.

Дополнение 14.10.2026: OGF `D_TREE` diffuse detail из `.thm` проходит через отдельный surface descriptor и девять статических/skinned/double-sided SPIR-V вариантов, получает UV scale также в forward и skinned draw; проверки SPIR-V отражают binding 2 и push offset 68. `MODEL` не включает diffuse detail по одной лишь `.thm`, поскольку его исходный Compile не читает `s_detail`. Общий граф теперь выдаёт точные ошибки ролей и режимов, отражает depth write `PARTICLE SET`; UI воспроизводит исходные alpha blend factors. Синтетическое пересечение detail, модели и частицы проверяет общую стабильную сортировку и результат compositing в одном пикселе. Это host-свидетельство, не визуальная приёмка на Android.

После этого дополнения повторно собраны host `xrRenderVK` и ARM64 native `libmain.so`; семь профильных C++-тестов, четыре проверки shader assets и SPIR-V detail прошли. Предыдущий SHA выше относится к предшествующей сборке.

Дополнение 14.10.2026: в промежуточном коммите `4bfcb7bf` opaque `MODELEbB` был ошибочно направлен в отражающий cube shader. Исходный R2 blender направляет непрозрачный вариант в обычный deferred `model/base`, без чтения environment. Текущий код исправляет маршрутизацию и сохраняет сериализованные environment поля; cube используется только blended `MODELEbB`. `S_SET` world SET, ADD/MUL/MUL_2X и варианты 2R/4R имеют отдельные forward shader/pipeline состояния; SET пишет глубину, SET 2R использует исходный alpha-порог 0. ARM64-only APK предыдущего среза имела SHA-256 `40938cce7de5aa16e72c56ea293f299dfdaa6c23f60e36d24e53de7c4516d67c` и **не содержит последующее исправление MODELEbB**. Комплект Android SDK/NDK/зависимостей восстановлен из сохранённой сборочной системы. Итоговые проверки нового кода и APK записываются после пересборки.

Лог CoP от 14.10.2026 подтвердил запуск `c22f49a2` и прохождение прежнего сбоя
`General / Priority` на mesh 12. Подготовка уровня остановилась на mesh 1408:
`mtl\\mtl_control_center_door_01.thm` сохраняет флаги detail, но не задаёт
имя detail texture. Обычный `TextureDescrManager` не создаёт association без
имени; Vulkan теперь также выключает оба detail usage при пустом имени,
продолжая разбирать bump/material metadata. Host fixture проверяет отсутствующий
и пустой `THM_CHUNK_DETAIL_EXT` и чтение через VFS. APK 0.9.135 прошла mesh 1408
и остановилась на mesh 4569: `BmmDold` v3, `levels\\zaton_asfalt`, сериализует
`Detail map / Name` вместе с четырьмя `R2-*` каналами. Исходный `deffer_impl`
читает четыре канала в HQ и не читает одиночное имя; Vulkan теперь сохраняет
его в definition, но выбирает terrain mask и четыре канала без `single_detail`.
Host-фикстура проверяет свойства и граф. APK 0.9.136 на устройстве снова
остановилась на mesh 4569: `Detail map / Transform` в том же `BmmDold` v3.
Исходный четырёхканальный `impl` не связывает `oT2_xform`, поэтому Vulkan
сохраняет матрицу в свойствах, но не требует её исполнения при четырёх
каналах. Для одиночного detail-варианта именованная матрица по-прежнему
неподдерживаема (N1). APK 0.9.137 прошла mesh 4569 и остановилась на mesh 4726:
`effects\\water` (`S_SET` v4) сохраняет `Base Texture / Name`. Исходный
программируемый `S_SET` связывает `C.L_textures[0]`, игнорируя сохранённые
`Name` и `Transform`; Vulkan теперь принимает эти поля только для `S_SET`,
сохраняет исходные значения, а ресурс продолжает выбирать из списка уровня.
Host-фикстуры проверяют water и UI с произвольными полями и отказ другого
класса при нестандартном селекторе. APK 0.9.138 ожидает проверки на устройстве;
полная загрузка и изображение уровня ещё не подтверждены.
