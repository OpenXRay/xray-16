# Статус 33 задач из PDF «OpenXRay Vulkan: план завершения 102–103»

Источник: присланный пользователем `openxray-vulkan-plan-102-103.pdf`, 12.10.2026. Нумерация ниже относится к **этому PDF**, а не к пунктам 1–103 старого `VULKAN_RENDERER_PLAN.md`. [Конечная цель и правило неизменяемого объёма](VULKAN_FINISH_LINE.md) отделяют исходные подпункты от новых самостоятельных задач. Состояние отражает текущее дерево ветки PR. «Частично» означает, что критерий «Готово, когда» в PDF ещё не доказан. Изображение и frame-time на устройстве не проверены.

Предыдущий срез 14.10.2026: `BmmD` v3 сохраняет четыре `R2-*` слота, четыре `$null` допускают одноканальный detail, неполный набор получает точный отказ. Тогда opaque `MODELEbB` отклонялся при разрешении материала; этот отказ исправлен после сверки с исходным `uber_deffer("model", "base")`. Семь профильных host-тестов прошли. ARM64-only APK 0.9.133 этого предыдущего среза имел SHA-256 `34619979eacae421c3d8124c7f7fbb80c3b557161f1c8307fed40d8b136efdcb`.

Дополнение 14.10.2026: OGF `D_TREE` diffuse detail из `.thm` проходит через отдельный surface descriptor и девять статических/skinned/double-sided SPIR-V вариантов, получает UV scale также в forward и skinned draw; проверки SPIR-V отражают binding 2 и push offset 68. `MODEL` не включает diffuse detail по одной лишь `.thm`, поскольку его исходный Compile не читает `s_detail`. Общий граф теперь выдаёт точные ошибки ролей и режимов, отражает depth write `PARTICLE SET`; UI воспроизводит исходные alpha blend factors. Синтетическое пересечение detail, модели и частицы проверяет общую стабильную сортировку и результат compositing в одном пикселе. Это host-свидетельство, не визуальная приёмка на Android.

После этого дополнения повторно собраны host `xrRenderVK` и ARM64 native `libmain.so`; семь профильных C++-тестов, четыре проверки shader assets и SPIR-V detail прошли. Новый ARM64-only APK 0.9.133 прошёл Gradle assembleDebug, проверку Vulkan route, 16K alignment и подписи. SHA-256 нового APK: `1edb15a732be99d728ae49e6162242ab1e582c4e5cfacba164db8f9c02c9a69e`. Предыдущий SHA выше относится к предшествующей сборке.

Дополнение 14.10.2026: в промежуточном коммите `4bfcb7bf` opaque `MODELEbB` был ошибочно направлен в отражающий cube shader. Исходный R2 blender направляет непрозрачный вариант в обычный deferred `model/base`, без чтения environment. Текущий код исправляет маршрутизацию и сохраняет сериализованные environment поля; cube используется только blended `MODELEbB`. `S_SET` world SET, ADD/MUL/MUL_2X и варианты 2R/4R имеют отдельные forward shader/pipeline состояния; SET пишет глубину, SET 2R использует исходный alpha-порог 0. ARM64-only APK предыдущего среза имела SHA-256 `40938cce7de5aa16e72c56ea293f299dfdaa6c23f60e36d24e53de7c4516d67c` и **не содержит последующее исправление MODELEbB**. Комплект Android SDK/NDK/зависимостей восстановлен из сохранённой сборочной системы. Итоговые проверки нового кода и APK записываются после пересборки.

Следующий срез 14.10.2026: статические/skinned OGF с `S_SET` используют режимы 0–9 world forward без подмены ADD/MUL обычным alpha blend. Флаг Fog у world BLEND теперь использует unlit fog shader; несогласованные fog-варианты отклоняются по имени свойства. Непрозрачный `MODELEbB` перенаправлен на исходный deferred model/base. Host `ctest` без оконного validation сценария прошёл 37/37, shader Python — 6/6; ARM64 native, assembleDebug и package/Vulkan-route checks прошли. Новая APK: SHA-256 `f4cc8205ee3f930877f8a76b50e6724282a92e1b17fb4e4886bdbd52b31fb2d7`. Оконный validation сценарий не запускается с доступной SDL; изображения и frame-time на устройстве не получены.

Текущая правка пунктов 1/4/5: UI `S_SET` с `Texture clamp=false` теперь получает отдельный wrap descriptor, в том числе для последовательности и OGM; reload перепривязывает оба sampler-варианта. OGF `S_SET` 0–9 больше не использует level-fragment с отсутствующими у skinned-модели входами baked/lightmap: добавлены десять `OBJECT_GEOMETRY` SPIR-V variants, mock blend/depth и проверка интерфейса. Host `ctest` прошёл 37/37 без оконного validation сценария, shader Python — 7/7. ARM64-only APK прошла Gradle assembleDebug, проверку Vulkan route и пакета; SHA-256 `e8687b10db16aa7ed584fab1cfe59696a967945a49b4bcbbce8563fb1878a017`. Эта правка **не закрывает** ещё именованные texture matrices, нестандартный priority и полную контекстную матрицу HUD/world flags.

Следующая правка 1/5: `S_SET` сохраняет clamp/wrap также в 20-слотовом surface descriptor при bump/normal metadata; ключ кэша и reload учитывают адресацию. World `S_SET BLEND + Fog` теперь записывает `Alpha ref` в push constants перед draw. Host-фикстуры проверяют оба случая. Именованные texture matrices, нестандартный priority и неполная HUD/world матрица остаются открытыми.

Дополнение 1/4/5: OGF `S_SET` в HUD получил собственные 10 `OBJECT_GEOMETRY` SPIR-V вариантов, pipeline для статической/скелетной геометрии, отдельные depth/blend состояния и передачу `Alpha ref`. Граф и mock pipeline проверяют режимы 0–9; world и HUD пары могут сосуществовать для одного OGF. Host `ctest` 37/37 без оконного validation, shader Python 7/7. ARM64 APK прошла сборку и проверки Vulkan route/пакета, SHA-256 `b588b2f41a2c58cfba4aa8090fe02bb5f2397edc0a4ea13cbeed3be149a7`. Остаются именованные матрицы, нестандартный priority, depthless/lighting/fog/water сочетания и проверка изображений на устройстве.

Срез 2–6 от 14.10.2026: detail-прототипы теперь сохраняют diffuse/bump/normal роли из `.thm`, отдельный transparent shader с forward lighting/fog и UV scale. `S_SET` для particle consumer разделён с `PARTICLE`: режимы 0–5 имеют свои HUD-варианты и исходные пороги alpha и depth; несовместимые Z/Fog/Lighting flags явно отклоняются. Host `ctest` без оконного validation — 37/37; ARM64 APK прошла native, Gradle assembleDebug, проверку shader assets, Vulkan route и пакета; SHA-256 `a88f3c3fc84091a858357bb0d50b0449d427684975791a5d6f70e3fc1bfea14d`. Device acceptance отложен до завершения реализации 102.
