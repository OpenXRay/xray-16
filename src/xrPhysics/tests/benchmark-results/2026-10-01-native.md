## Further local optimization

The `2026-10-01-local-second-*` files report the later dry-region cache and
lazy ray-result changes, based on `25ad9bb2e`. This further draft followup
includes the source and findings. Baseline runtime: `native-game-bin-performance-final`; candidate
core SHA256 `83B1F5666EF1E5E977569FCB246FDA815C43FBF723445392EBF17251331D7BBA`.

- `local-second-physics.csv` / `local-second-queries.csv`: three runs each of
  baseline and candidate at one/four workers, twelve accepted captures.
- `local-second-four-repeat-physics.csv` / `local-second-four-repeat-queries.csv`:
  three further runs each at four workers, six accepted captures, added because
  the first four-worker ragdoll result had wide overlapping run ranges.

Both sets use the same previously described save, engine, settings and matched
compiler dependency. Report them separately: idle and ray gains repeat, but
the four-worker ragdoll median changes direction. All eighteen accepted runs
pass all 35 game checks and save/reload validation. An ambiguous reload-exit
rejection in the first set and a confirmed `0xc0000005` reload in the repeat
are excluded and retained. Diagnostic minidumps reproduce shader-compiler
exit heap cleanup failures with candidate and frozen baseline. Updating the
compiler alone does not remove the observed exception; cause remains unresolved.

Details, raw capture paths, hashes and exclusions are in
[NativePerformance.md](../../NativePerformance.md#further-local-optimization).

## Files and units

| File suffix | Contents | Units |
| --- | --- | --- |
| `physics.csv` | Medians of process means, per-process p95 medians, run ranges, frame intervals, workload counters, memory and reload counts | Time in ms; memory in MiB |
| `queries.csv` | Medians of per-process query medians, run ranges and reported static model memory | Time in microseconds/query; model memory in bytes |
| `scenes.csv` | Synthetic medians of process means/p95, process CPU, memory and ODE wall-time ratio | Time in ms/step; memory in MiB; ratio is native/ODE (lower is faster) |

`initial` and `optimized` in the filenames identify the capture sets, rather
than every row's implementation: the optimized set includes the original port
as a comparator. ODE island-body and native active-body/character counters
have different definitions. The native integration and ODE solver columns
also have different scopes; compare complete step times.

## Method and exclusions

Game: same engine executable, isolated Zaton save/assets, 800x600 R2 renderer,
VSync off, 100 Hz physics, 18 iterations, `mt_physics off`; idle and 12 driven
ragdolls, deterministic queries, saving, process shutdown and reload. Native
captures pass 35 loaded-game checks. Reload placement permits the documented
1 m physical-root displacement around asynchronous saving/loading.

Synthetic: 2 kg unit boxes, 0.7 friction/0.1 restitution floor on both backends,
0.05 damping, 100 warmup + 500 timed 10 ms steps, 18 iterations. No gameplay
callbacks are installed. Native temporary allocator remains 32 MiB. Different
solvers produce different contacts and trajectories. CPU counters include
validation/output and have coarser resolution than wall timings.

No compilation ran during timing; contact profiling and CDB test hooks were
disabled. An earlier synthetic capture with mismatched floor friction is
excluded. The initial game set retained an ODE reload failure against an
earlier 0.5 m bound and reran it with the documented 1 m bound.

In the optimized set, one zero-worker main process returned `0xc0000005`
after its quit log despite passing gameplay/saving and the separate reload.
That failed capture and a debugger-attached capture are excluded; replacement
captures exited cleanly. Ten additional monitored reload/shutdown processes
also exited normally. The original shutdown failure remains unexplained;
passing replacements do not establish a fix.

Full timing CSVs, hashes, configuration metadata, logs and validation saves
remain local at the paths in the two reports. Game assets and saves are not
included here. Reproduction scripts and tests are committed with the migration.
