# OPCODE 1.3 compared with OPCODE 1.2 and Jolt

The OPCODE update is independent of the Jolt migration. The synthetic box
workload improved by 35.7%, while nearest rays were effectively unchanged,
construction/destruction took 20.7% longer and warm cache loading/destruction
took 10.2% longer. Heavy combat was mixed: the first ten seconds were unchanged
in Call of Pripyat and 13.2% faster in Clear Sky. Full thirty-second results
were +8.2% and -3.8% respectively. This is a local comparison, not evidence
of a general FPS increase.

## Independent implementation

Branch `followup/opcode-1.3` is based on upstream `dev` at
`4c27925c4c500aecd090004643e9350fd7c380db`. It contains no Jolt prerequisite.
[Issue #2139](https://github.com/OpenXRay/xray-16/issues/2139) and
[the earlier OPCODE discussion](https://github.com/OpenXRay/xray-16/issues/877#issuecomment-2637054334)
referenced `solbjorn/OpCoDe`, which was unavailable during this work.
Instead, this update vendors the OPCODE 1.3 implementation in
[OGSR/OGSR-Engine, pinned revision](https://github.com/OGSR/OGSR-Engine/tree/01faa139995f6afdc66addb48065f053d38f397e/ogsr_engine/xrCDB/OpCoDe).
All 98 downloaded files were verified against their Git blob hashes.
The distribution identifies itself as 1.3; this is not claimed to be the
exact unavailable solbjorn fork or a separately verified 1.3.2 release.

X-Ray retains its collision traversal and triangle intersection algorithms.
The new MeshInterface uses the existing vertex/triangle arrays with strides,
remapping disabled, and lifetime tied to the model. A separate `.opcode13`
cache prevents collisions with 1.2 caches. Legacy embedded level.cform trees
remain supported, with validation and a geometry rebuild on invalid nodes.
See [integration details](../../../../Externals/OPCODE13/Integration.md).

## Measurement protocol

AMD Ryzen 9 9955HX, 16 cores / 32 logical processors; NVIDIA RTX 5070 Ti Laptop;
32 GB installed memory; Windows x64, MSVC 19.44.35229 Release. Games use R2,
800x600 windowed, VSync off, 501 FPS cap, 100 Hz physics, 18 iterations,
`mt_physics off`. No compilation, synthetic benchmark or diagnostic profiler
ran concurrently with accepted gameplay captures. Game archives are junctions,
unchanged runtime files are hardlinks, and one scratch workspace/cache is reused
per game. No full crash dumps were generated for this comparison.

Four runtime labels are used throughout:

| Label | Static collision | Dynamics |
| --- | --- | --- |
| ODE | Existing OPCODE 1.2 | ODE |
| Opcode13 | New OPCODE 1.3 | ODE |
| JoltODE | Existing Jolt collision bridge | ODE |
| Native4 | Current native Jolt collision/physics | Jolt, four workers |

OPCODE 1.2, OPCODE 1.3 and JoltODE share the same engine, core, game DLL and
ODE physics DLL. Native4 uses its already built matching game/physics DLLs;
its entire FPS difference cannot be attributed only to static collision.
The independent production update retains the upstream MODEL ABI. An external
benchmark overlay adds the existing benchmark branch's atomic status/thread
field to match its frozen game DLLs. No production ABI change is introduced
by that overlay. The separate production build/tests use the upstream layout.
Raw captures and build logs are under `C:/code/migration-benchmark`;
compact tables and binary/input provenance accompany this report.
All four xrCDB comparison builds use CMake Release `/O2 /Ob2 /fp:precise`
with the release DLL CRT. The existing 1.2 OPCODE DLL comes from the native
Release build, while the new 1.3 DLL uses the component CMake build. Thus
builder timings also include a library build-profile difference; they should
not be read as an isolated algorithm-only comparison. The custom query code
is compiled in xrCDB with matching optimization settings.

## Heavy combat

Fresh matrix: four runtimes, three passes, two games, **24 accepted runs**.
Order reverses on pass two. Each game reloads the same prepared save of 50
NPCs, two opposing groups of 25, normal health, AK74s and ordinary ammunition.
NPC movement is enabled. The stationary actor selects targets, aims, fires
bursts and reloads through normal actor input. It does not inherit the NPC
navigation/cover/squad planner. CoP uses Zaton near (256,16,510); Clear Sky
uses a central dry field in the Marshes near (240,3,70), with the actor beside
its allied group. No god mode, scripted kills, healing, replacement spawning
or driven ragdolls.

The summarizer verifies matching save/script/config hashes and all 50 NPC
identity/loadout records, initial population, both sides taking hits, actual
actor/NPC shots and corpse shells. Every accepted run passed these checks.
FPS is 1000 / mean measured frame interval, then median over three runs.
Physics is complete step time, using the first ten seconds of cumulative
simulated timestep. Frame p95 is the median of per-run percentiles.

| CoP | Opcode13 | 133.7 | 133.2-136.8 | -0.4% | 15.83 | 0.271 |
| CoP | JoltODE | 122.8 | 119.3-128.2 | -8.6% | 16.37 | 0.263 |

## Synthetic collision workloads

32,768 terrain triangles; 20,000 queries per timed ray/box batch. Each process
performs warm-up and five timed samples per metric; the table is the median
of three independent process medians, with alternating runtime order.
Build/cache metrics include destruction and adapter/validation work, so these
are integration timings rather than isolated upstream-kernel timings.

| Runtime | Build/destroy ms | Nearest rays ms | Full boxes ms | Warm cache load/destroy ms |
| --- | ---: | ---: | ---: | ---: |
| ODE | 8.539 | 4.250 | 44.371 | 5.052 |
| Opcode13 | 10.309 | 4.253 | 28.515 | 5.567 |
| JoltODE | 4.890 | 6.081 | 72.982 | 7.584 |
| Native4 | 10.521 | 6.594 | 40.737 | 13.252 |

All 12 processes exited zero, returned 980,000 aggregate box hits and the
same nearest-distance signature (200000.134). This benchmarks Native4's
collision adapter, not its physics solver. Its worker count does not measure
parallel solver throughput here.

## Queries against loaded levels

24 accepted process captures: two games, four runtimes, three passes with
pass two reversed. Each process waits ten seconds after loading the original
non-combat save, then runs 4,096 fixed-seed probes per workload, one warm-up
and seven timed batches. Origins are literal (256,16,510) in Zaton and
(240,3,70) in the Marshes, independent of actor settling. Values are median
microseconds per query, first over batches and then over process captures.
Smaller is faster; ranges are recorded in the accompanying CSV.

| Game | Runtime | Nearest ray µs | Any ray µs | Full box µs | Box time change vs 1.2 |
| --- | --- | ---: | ---: | ---: | ---: |
| CoP | ODE | 0.636 | 0.414 | 0.502 | baseline |
| CoP | Opcode13 | 0.613 | 0.393 | 0.368 | -26.7% |
| CoP | JoltODE | 0.513 | 0.351 | 0.792 | +57.9% |
| CoP | Native4 | 0.684 | 0.500 | 0.506 | +0.9% |
| Clear Sky | ODE | 0.892 | 0.516 | 4.946 | baseline |
| Clear Sky | Opcode13 | 0.743 | 0.434 | 3.200 | -35.3% |
| Clear Sky | JoltODE | 0.651 | 0.379 | 8.820 | +78.3% |
| Clear Sky | Native4 | 0.761 | 0.531 | 2.951 | -40.3% |

OPCODE 1.3 nearest/any-ray time fell 3.6%/5.3% in CoP and 16.7%/15.8% in
Clear Sky. JoltODE has faster rays here but slower full boxes. Native4 has
the fastest Clear Sky full boxes, while its combat FPS remains lower.
The query workloads measure static geometry; solver parallelism is not tested.

All 24 captures exited zero. Within each game, all backends returned the same
hit counts and exactly the same recorded nearest-distance sum. Every CoP ray
batch returned 2,502 hits and every full-box batch 20,513; Clear Sky counts
are recorded in the summary. There is no hit-count substitution behind the
reported OPCODE 1.3 gains. Fixed probes improve repeatability but do not
represent every location or query distribution in either game.

## Validation and stability

The new component CMake project compiled the production ABI with matching
native dependencies. Both CTest cases passed: synchronous and `-mt_cdb`.
Checks cover ray/box/frustum flags, boundaries, independently checked random
geometry, triangle metadata, cache roundtrips, missing/truncated/corrupt
caches, preservation of the original cache, an actual x64 1.2 serialized
tree, embedded trees without a checksum, and damaged-tree recovery.
The comparison ABI overlay also passed synchronous/threaded checks.
The native OPCODE Visual Studio project compiled Release x64 with zero
warnings/errors, including the repository's C++20 and warnings-as-errors
settings. That verification DLL was not substituted into the frozen timings.
Native xrCDB Release x64 compilation also passed with zero warnings/errors;
the production DLL link and runtime checks used the component CMake build.

Three CoP attempts completed the timed combat and DONE marker, then exited
with access violation `0xC0000005` after `KERNEL:QUIT`: Native4 run 1 once,
Opcode13 run 2 twice. They are retained under `excluded-captures` and excluded
from accepted-run metrics. An additional Opcode13 run monitored with a
small-dump-on-crash diagnostic exited zero, produced no dump and is excluded
from timing. No stack was captured for these failures, so their cause is
unresolved; the fact that both runtimes failed does not exonerate either.
Successful reruns do not establish production stability.

An initial CoP query dataset used Y=0, below terrain, and returned zero box
hits. It was stopped and excluded in full. The reported query matrix uses
the corrected fixed Y=16 origin. No combat fixture or combat timings were
changed by that correction.

## Reproduction

Build instructions are in [Integration.md](../../../../Externals/OPCODE13/Integration.md).
Run CTest with the matching native runtime on PATH. `xrCDBBenchmark.exe`
writes synthetic JSON to the optional path supplied as its first argument.
`opcode_queries.script` uses the existing benchmark-enabled physics DLL to
probe static geometry with fixed origins. The gameplay harness is
`misc/windows/benchmark-gameplay.ps1` on the Jolt benchmark branch; its query
variant copies `opcode_queries.script`, runs it, and retains only
`benchmark-queries.csv`, metadata and logs. It does not run combat or a driven
physics workload. `SummarizeComparisons.ps1` validates and summarizes three
query captures per runtime/game plus the 12 synthetic captures.

Combat roots: `opcode13-cop-combat-20261002`, `opcode13-cs-combat-20261002`.
Query roots: `opcode13-cop-ground-queries-20261002`,
`opcode13-cs-ground-queries-20261002`. Runtime manifest, source-download
manifest, build/test logs and frozen candidate are under `opcode13-development`.
Archives, saves, caches, crash dumps and binaries are not included in this
source branch.
